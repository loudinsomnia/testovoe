## 2. Дефекты

Общие условия для всех шагов: открыта <https://rcsi-science.github.io/demo-roomly/>, остальные поля заполнены корректно, если шаг не говорит иное. Корректный набор: Средняя, дата через 7 дней, 10:00–11:00, 4 участника, имя «Анна Смирнова», почта `anna.smirnova@company.ru`.

### BUG-01. Длительность вне диапазона 30 минут – 4 часа принимается

**Условия.** Форма доступна, дата в будущем, окончание позже начала.

**Шаги.**

1. Заполнить корректный набор, но поставить окончание `10:15` (15 минут).
2. Нажать «Забронировать».
3. Повторить с интервалом `10:00–15:00` (5 часов).

**Ожидаемый результат.** Обе заявки отклоняются. Длительность должна быть от 30 минут до 4 часов.

**Фактический результат.** Обе заявки подтверждаются. В `validate` есть только сравнение «окончание раньше начала». Нижней и верхней границы длительности нет.

**Приоритет: High.** Можно забронировать встречу на несколько минут или на почти весь день. Это прямое нарушение правила длительности, и пользователь видит успешное подтверждение.

**Доказательство.** Проверка времени в `script.js`:

```javascript
if (data.startTime && data.endTime && data.endTime < data.startTime) {
  errors.endTime = 'Время окончания должно быть позже начала.';
}
```

Автотест `test_discovered_defect` проверяет интервал 10:00–10:15 и ожидает отказ.

### BUG-02. На сегодняшнюю дату можно выбрать уже прошедшее время

**Условия.** Проверка выполняется позже выбранного слота. Например, сейчас после 11:00, а интервал — 09:00–10:00. Дата в поле — сегодня.

**Шаги.**

1. Оставить дату сегодняшней.
2. Указать начало и окончание, которые уже прошли.
3. Заполнить комнату, участников, имя и почту корректными значениями.
4. Нажать «Забронировать».

**Ожидаемый результат.** Форма не даёт выбрать прошедшее время для текущего дня.

**Фактический результат.** Заявка подтверждается. Минимальная дата выставляется на сегодня (`dateInput.min`), сравнение с текущим временем отсутствует.

**Приоритет: High.** Правило названо отдельно от запрета прошлой даты. Прошлая дата отклоняется, прошедший слот сегодня — нет, поэтому бронь на уже прошедшее время выглядит созданной.

### BUG-03. Одинаковое время начала и окончания принимается

**Условия.** Дата в будущем, начало и окончание — одно и то же значение, например `10:00` и `10:00`.

**Шаги.**

1. Заполнить корректный набор с одинаковым началом и окончанием.
2. Нажать «Забронировать».

**Ожидаемый результат.** Ошибка «Время окончания должно быть позже начала.» Бронь не создаётся.

**Фактический результат.** Условие в коде строгое: `endTime < startTime`. Равенство его не выполняет, ошибка не показывается, заявка подтверждается. Нулевая длительность заодно нарушает минимум в 30 минут из BUG-01, но здесь не срабатывает уже написанная проверка.

**Приоритет: High.** Форма сообщает, что встреча создана, хотя окончания позже начала нет.

### BUG-04. Слишком слабая проверка формата почты

**Условия.** Остальные поля корректны.

**Шаги.**

1. Ввести почту `user@company@ru.com`.
2. Нажать «Забронировать».
3. Повторить с `a@b.c`.

**Ожидаемый результат.** Почта отклоняется с текстом «Введите корректную рабочую почту.»

**Фактический результат.** Оба адреса проходят выражение `/^\S+@\S+\.\S+$/` и получают подтверждение брони. Адрес без точки в домене (`anna.company.ru`) отклоняется — эта ветка работает, её покрывает негативный автотест.

**Приоритет: Medium.** Ошибочный адрес доходит до сообщения об успехе. Отправки на сервер нет, поэтому ущерб ограничен неверным подтверждением на странице.

### BUG-05. При числе участников больше 20 скрывается лимит комнаты

**Условия.** Выбрана Малая комната (вместимость 4).

**Шаги.**

1. Указать 25 участников.
2. Остальные поля заполнить корректно.
3. Нажать «Забронировать».

**Ожидаемый результат.** Заявка отклоняется, и пользователь видит лимит выбранной комнаты: максимум 4.

**Фактический результат.** Заявка отклоняется, но второе присваивание затирает первое. На экране остаётся только «Количество участников — от 1 до 20.» По этому тексту 15 участников выглядят допустимыми, хотя для Малой комнаты это не так.

**Приоритет: Medium.** Некорректная бронь не создаётся, но подсказка противоречит вместимости. Для 5 участников в Малой комнате отдельное сообщение «В комнате максимум 4 участника.» сохраняется.

**Доказательство.**

```javascript
if (data.room && data.participants && Number(data.participants) > capacities[data.room]) {
  errors.participants = `В комнате максимум ${capacities[data.room]} участника.`;
}
if (data.participants && (Number(data.participants) < 1 || Number(data.participants) > 20)) {
  errors.participants = 'Количество участников — от 1 до 20.';
}
```

Дополнительно, вне пятёрки: имя подставляется в статус через `innerHTML`, поэтому строка вроде `<img src=x onerror=...>` попадает в разметку. Сообщение не сохраняется и никому не отправляется, это отражение в той же вкладке. Для 10 и 20 участников текст «максимум N участника» грамматически неверный. Оба замечания Low относительно правил бронирования.

## 4. Вопросы, допущения, покрытие, риски

### Вопросы и допущения

- Границы длительности включительные: 30 минут и 4 часа считаются допустимыми. В требованиях это не сказано явно.
- «Прошедшее время» для сегодняшнего дня относится и к началу, и к слоту, который уже завершился. Слот, который начался в прошлом и ещё идёт, в требованиях не разобран.
- Один календарный день не переходит через полночь. Окончание `00:30` при начале `23:00` считается раньше начала, потому что сравнение строковое.
- «Корректная почта» — один символ `@`, домен с точкой и зона из двух и более символов. Корпоративный домен в требованиях не задан, поэтому `name@company.ru` и `name@gmail.com` оба приняты как формально верные.
- Число участников целое. Поле `type="number"` позволяет ввести дробь, отдельного правила для этого нет.
- Дата в подтверждении остаётся в формате `ГГГГ-ММ-ДД`, как значение поля. Отдельный формат отображения не задан.
- Сообщение об успехе должно содержать комнату, дату, время и имя. Точная пунктуация сверена с текущей строкой в `script.js`: короткое тире `–` и точка `·`.

### Что разобрано

По коду формы разобраны обязательность полей, прошлая дата, сравнение начала и окончания, вместимость комнат, диапазон 1–20, формат почты, текст успеха, отсутствие отправки (`preventDefault`) и сброс статуса при новом вводе. Справочник комнат в `index.html` совпадает с вместимостью в `script.js`.

### Риски и ограничения

- Чек-лист не пройден руками, скриншотов нет. Дефекты подтверждены чтением `validate`, а не кликами по опубликованной странице.
- Автотесты не запускались: нет `artifacts/junit.xml` и нет фактического статуса pass/xfail.
- Позитивный тест зависит от текста успеха. Если формулировку изменят, а набор данных останется верным, тест упадёт.
- Дата «сегодня + 7 дней» считается в часовом поясе машины, где запущен pytest. Минимальная дата в браузере считается в поясе браузера. В штатном Docker-прогоне это одна среда.
- Прошедшее время (BUG-02) в автотест не выносилось: результат зависит от текущего часа, ночью такой сценарий легко собрать неверно.
- Не проверялись пересечение броней, часовые пояса офиса, доступность комнаты и мобильная вёрстка. Для одностраничной формы без сервера этих данных нет.
- Приложение намеренно не исправлялось.

Из корня репозитория, Docker и Docker Compose v2:

```bash
docker compose run --build --rm tests
```

Команда собирает образ `mcr.microsoft.com/playwright/python:v1.64.1-noble`, ставит зависимости из `requirements.txt` и запускает `pytest`. Вместе с тремя тестами кандидата выполняется smoke-тест каркаса.

Отчёты:

- `artifacts/junit.xml`
- `artifacts/browser/` — скриншот и trace упавших тестов

Без Docker:

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m pytest
```

Браузер задан в `pytest.ini`: Chromium. Версии пакетов: Playwright 1.64.1, pytest 8.3.5, pytest-playwright 0.7.1.
